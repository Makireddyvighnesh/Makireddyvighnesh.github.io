Mini LLM inference engine INFERENCE Built to understand what really happens when an LLM serves requests. Qwen3-4B on an L4 GPU.

I wanted to understand inference, not just call it: what the metrics mean, what breaks under load, and why. So I built a small engine and implemented the core ideas myself.

  • Continuous batching and a request scheduler
  • Prefix caching to reuse shared prompt prefixes
  • Split-KV attention
  • CUDA graphs to cut launch overhead

Telugu RL environments + GRPO RL Transliteration exact match from 4.6% to 29.1% on a 1.5B model, trained through my own environment.

Reinforcement learning environments for Telugu built on OpenEnv, covering transliteration, OCR, ASR and translation, from open datasets (Aksharantar, FLEURS, Samanantar and others). Each one serves a task, grades the answer against a hidden reference, and blocks reward hacking: empty, looping or ballooning answers score zero.

Text-to-SQL with SFT + GRPO RL Qwen3-4B with execution rewards: 86.7% pass@4 on Spider, 70.7% on BIRD.

Fine-tuning on examples teaches a model to write SQL that looks right. But a query is only right if it runs and returns the right rows.

I generated and validated 9,000+ chain-of-thought SQL examples with DeepSeek, fine-tuned Qwen3-4B with 4-bit QLoRA, then trained with GRPO using a reward that executes each query. That improved pass@1 by 10% over the SFT model.
